# 采集数据说明

以下命令均在 `MocapLive/mobileposer` 目录下运行。`p01`、`p02` 是受试者编号示例，可按实际情况替换；编号只能包含英文字母、数字、下划线和连字符，且必须以字母或数字开头。

## 通用采集流程

1. 每条序列都要在 iPhone 和 Apple Watch 上开始一段**新的本地采集**，保证两个设备使用同一次会话。采集期间不要打开 iPhone 或 Watch 到电脑的 UDP 实时传输。
2. 按终端提示佩戴设备并完成离线 walking calibration：**双手自然并拢静止（N-pose）—直线向前走一步并停稳—双手自然并拢静止（N-pose）**。戴手表的一侧手臂全程保持固定，前走时不要摆臂或旋转手腕；手机不要在口袋里转动。
3. 标定阶段只记录，不在电脑端实时判定成功或失败。完成第二段静止后，回到动作起点，等待提示音后完成 20 秒正式动作，默认输出 30 FPS。两台设备的完整本地文件会在导入后分别计算 `R_MI` 和 `R_SB`。
4. 动作结束后，停止两台设备的本地采集，等待 Watch 文件完整传到 iPhone，再回到终端确认。脚本会保存三段标定及正式动作的电脑端时间注释。
5. 默认采用批量导入：先录完全部计划，再通过 USB 将全部原始 `.ndjson`/`.jsonl` 文件复制到对应原始数据目录，最后运行 `--finalize-batch`。不要在文件尚未复制完整时开始整理。
7. 中断后使用原命令继续。已有 `capture.json` 或 `labels.pt` 的条目会按状态跳过，不要混用不同受试者或不同采集条件的数据目录。

## 时间基准、标定窗与 USB 离线整理

每个 `device_motion` 事件都带有设备侧的 `timestampUnixNs`。采集脚本在电脑端记录
第一段静止、前向走、第二段静止和动作窗，分别位于
`capture.json -> windows.npose`、`windows.forward_walk`、`windows.post_static` 和
`windows.action`。这些时间仅作采集审计；离线标定使用每台设备的完整本地序列定位
“静止—前走—静止”协议，而不是依赖 UDP 收包时间。

整理时默认保留设备自己的 Unix 时间轴：

```text
corrected_pc_unix_s = timestampUnixNs / 1e9 + device_time_offset_s
```

- 默认 `device_time_offset_s = 0`，不再从 UDP 包推断时间偏移。
- 如已知某台设备的 Unix 时间有固定偏差，可在整理命令中显式提供
  `--iphone-time-offset <秒>` 或 `--watch-time-offset <秒>`。
- 设备 Unix 时间仅提供近似跨设备对齐；每设备 `R_MI`、`R_SB` 的计算不依赖两台设备逐样本同步。

因此，不要求在电脑和手表上“精确同时”按开始。正确要求是：在终端确认开始标定前，
iPhone 与 Watch 都已经开始本地采集，并且两台设备都完整覆盖三段标定及正式动作。若 Watch
开始过晚、结束过早，USB 导入后无法为该设备求解可靠的 `R_MI`、`R_SB`。

从 USB 导入后，脚本会在 `capture.json -> offline_calibration`、`meta.json -> calibration`、
`quality.json` 和 `labels.pt` 中保存**两台设备各自**的 `R_MI`、`R_SB`、标定样本数、
首尾 `timestampUnixNs`、序列号和质量结果。任何一台设备的标定无法完成时，本条不能作为
已整理训练/测试序列使用，应检查原始文件是否完整、佩戴是否固定，并按需要重录。

## 训练集采集

- 对应脚本：`collect_train_sequence.py`
- 动作：走路、慢跑、踢腿、坐、交叉臂、拍手、开合跳、拳击、挥手、站立。
- 采集规模：10 个动作 × 4 种佩戴（左/右手表 × 左/右口袋）× 3 组 × 2 种手机朝向，共 **240 条**。
- 两种手机朝向均为头朝下，分别为屏幕朝内（`screen_in`）和屏幕朝外（`screen_out`）。脚本会先录完一种佩戴及朝向下的动作，再提示切换条件。

### 1. 开始或继续采集

```powershell
python collect_train_sequence.py --subject p01
```

终端会显示当前应做的动作、佩戴位置、组数及手机朝向。按回车开始当前条；根据提示可输入 `s` 跳过，或输入 `q` 保存进度并退出。

### 2. 导入原始文件并生成标签

全部录完后，将原始文件复制到 `data/datasets/subjects/p01/train_raw`，再运行：

```powershell
python collect_train_sequence.py --subject p01 --finalize-batch
```

脚本会按 iPhone/Watch 的共同 `sessionID` 及采集时间顺序匹配原始文件，分别复核两台设备的离线标定并生成整理后的数据。

| 内容 | 默认目录 |
| --- | --- |
| 原始文件 | `data/datasets/subjects/p01/train_raw` |
| 逐条导入时的收件目录 | `data/datasets/subjects/p01/device_inbox` |
| 标签及采集清单 | `data/datasets/subjects/p01/train_labels` |

每条标签目录下主要包含 `capture.json`、`raw.ndjson`、`labels.pt`、`meta.json`、`quality.json` 和 UWB 曲线图。`labels.pt` 包含模型坐标系下的加速度、朝向、UWB 距离、佩戴槽位以及按设备保存的 `R_MI`、`R_SB`。

### 3. 可选运行方式

只采集一个动作的全部佩戴、组别及朝向组合：

```powershell
python collect_train_sequence.py --subject p01 --only-action Walking
```

试录一条到 `_trial` 目录，不占用正式计划：

```powershell
python collect_train_sequence.py --subject p01 --once --action Walking --watch lw --phone-pocket lp --group 1 --phone-facing screen_in
```

每条结束后立即通过 USB 导入并整理：

```powershell
python collect_train_sequence.py --subject p01 --import-each
```

检查脚本配置和标定逻辑：

```powershell
python collect_train_sequence.py --self-test
```

## 测试集采集

- 对应脚本：`collect_eval_test.py`
- 动作、4 种佩戴及 2 种手机朝向与训练集相同，但每个组合只录 **1 组**，共 **10 × 4 × 1 × 2 = 80 条**。
- 默认受试者为 `p02`；未提供 `--subject` 时也使用该编号。
- 采集、标定、设备本地文件和离线整理流程与训练集相同。

### 1. 开始或继续采集

使用默认受试者 `p02`：

```powershell
python collect_eval_test.py
```

显式指定其他受试者，例如 `p03`：

```powershell
python collect_eval_test.py --subject p03
```

### 2. 导入原始文件并生成标签

将文件复制到所选受试者的 `test_raw` 目录后，使用**相同的 `--subject`** 运行整理命令。例如：

```powershell
python collect_eval_test.py --subject p02 --finalize-batch
```

```powershell
python collect_eval_test.py --subject p03 --finalize-batch
```

以 `p02` 为例，默认目录如下；更换受试者时，将路径中的 `p02` 替换为对应编号。

| 内容 | 默认目录 |
| --- | --- |
| 原始文件 | `data/datasets/subjects/p02/test_raw` |
| 逐条导入时的收件目录 | `data/datasets/subjects/p02/test_inbox` |
| 标签及采集清单 | `data/datasets/subjects/p02/test_labels` |

### 3. 可选运行方式

只采集一个动作的全部佩戴及朝向组合：

```powershell
python collect_eval_test.py --subject p02 --only-action Walking
```

试录一条到 `_trial` 目录：

```powershell
python collect_eval_test.py --subject p02 --once --action Walking --watch lw --phone-pocket lp --phone-facing screen_in
```

每条结束后立即通过 USB 导入并整理：

```powershell
python collect_eval_test.py --subject p02 --import-each
```

检查测试计划：

```powershell
python collect_eval_test.py --self-test
```

### 标定时的手表手臂姿态

无论是旧版双 UDP 实时采集，还是当前本地记录模式，标定阶段都必须让戴手表的一侧手臂全程保持固定。N-pose 阶段保持不动；听到提示音后前走时不要摆臂或旋转手腕，尽量让手表相对身体保持同一姿态。另一侧手臂可以自然活动。这样可避免把手臂摆动误认为人体前进方向，降低手表独立 `R_MI` 的误差。
